# Паспорт проекта Whisper Mood

---

## 1. Общая информация

**Название:** Whisper Mood — веб-приложение для ведения личного дневника настроения.

**Происхождение:** собственный существующий проект, разработанный самостоятельно.

**Репозиторий:** [pampixz/full-stack](https://github.com/pampixz/full-stack).

**Тип приложения:** клиент-серверное веб-приложение.

**Состояние проекта:** существует реализованная версия приложения, требующая проверки воспроизводимости запуска, актуализации документации и совершенствования инженерных практик.

## 2. Назначение и решаемая проблема

**Whisper Mood** — веб-приложение для ведения личного электронного дневника, сохранения мыслей, событий и эмоциональных переживаний пользователя.

**Решаемая проблема:** отсутствие единого удобного пространства для систематического ведения личных записей, отслеживания эмоционального состояния и организации связанной с этим информации.

Приложение позволяет сохранять записи, просматривать их историю и управлять личными данными.

**Цель проекта:** создание удобной, безопасной и доступной веб-системы для ведения личного дневника с разграничением прав пользователей.

## 4. Три основные функции проекта

1. **Регистрация и авторизация пользователей.** Создание учётной записи, вход в систему и разграничение доступа по ролям.
2. **Управление записями дневника.** Создание, просмотр, редактирование, удаление и поиск личных записей.
3. **Работа со встречами.** Просмотр информации о встречах и административные операции по управлению ими.

### 10.1. Основные каталоги

## Структура проекта

Проект Whisper Mood представляет собой клиент-серверное
веб-приложение с разделением ответственности между
клиентской частью, серверной частью и базой данных.

| Каталог | Назначение |
|---|---|
| backend/app/api/v1/ | Обработчики REST API |
| backend/app/core/ | Конфигурация, безопасность и права доступа |
| backend/app/db/ | Подключение к базе данных |
| backend/app/models/ | Модели предметной области |
| backend/app/repositories/ | Работа с данными через репозитории |
| backend/app/schemas/ | Схемы входных и выходных данных |
| backend/app/services/ | Сервисный слой |
| frontend/src/components/ | Компоненты интерфейса |
| frontend/src/pages/ | Страницы приложения |
| frontend/src/routes/ | Маршрутизация и защита страниц |
| frontend/src/shared/ | Общие модули клиентской части |
| tests/unit/ | Модульные тесты backend |
| tests/integration/ | Интеграционные тесты backend |

| .github/workflows/ | Конфигурация GitHub Actions |
| docs/ | Документация проекта |

## Точки входа приложения

- Backend: backend/app/main.py.
- Frontend: frontend/src/main.tsx.
- Корневой компонент frontend: frontend/src/App.tsx.
- Маршруты API: backend/app/api/v1/routes.py.
- Запуск инфраструктуры: docker-compose.yml.
- Обратный прокси: nginx/nginx.conf.

## Внешние зависимости и сервисы

- MySQL 8.4.13 — реляционная база данных.
- OpenWeather API — внешний погодный сервис.
- Nginx 1.31.8 — веб-сервер и обратный прокси.
- Docker Compose — управление контейнерами приложения.
- GitHub Actions — автоматизация инженерных проверок.

### Хранение файлов

Вложения к записям дневника сохраняются в локальном
каталоге uploads/entries серверного приложения.

Метаданные файлов хранятся в базе данных MySQL.

Поддерживаемые форматы:

- JPEG;
- PNG;
- PDF;
- TXT.

Максимальный размер файла — 5 МБ.

Доступ к вложениям ограничивается правами пользователя
и принадлежностью записи.

Текущее ограничение: каталог вложений не подключён
к постоянному Docker-тому. При удалении и пересоздании
контейнера backend существует риск потери файлов.

## Конфигурация приложения

Основные файлы конфигурации:

- backend/app/core/config.py;
- docker-compose.yml;
- backend/Dockerfile;
- frontend/Dockerfile;
- nginx/nginx.conf.

Переменные окружения:

- DATABASE_URL — строка подключения к MySQL.
- OPENWEATHER_API_KEY — ключ внешнего погодного API.

Порты приложения:

- 8088 — единая точка доступа через Nginx.
- 8080 — серверное API.
- 3000 — клиентская часть.
- 3307 — внешний порт MySQL.

Nginx перенаправляет запросы /api/, /docs
и /openapi.json на backend, остальные запросы —
на frontend.

### Непрерывная интеграция

В проекте настроен GitHub Actions.

Workflow запускается при создании и обновлении
Pull Request, а также при отправке изменений в main.

Этапы CI:

1. Получение исходного кода.
2. Настройка Python.
3. Установка зависимостей Backend.
4. Запуск тестов Backend через pytest.
5. Настройка Node.js.
6. Установка зависимостей Frontend.
7. Запуск тестов Frontend.
8. Сборка Docker-образов.
9. Проверка конфигурации Docker Compose.

Автоматические тесты Backend в CI используют SQLite.

Фактическое автоматическое развёртывание приложения
на сервере не реализовано.

Успешность выполнения CI после последних изменений
требует отдельной проверки.

## 14. Первые наблюдения о проблемах проекта

### 14.1. Воспроизводимость сборки

**Наблюдение:** необходимо проверить фиксацию версий Python-зависимостей.

**Предлагаемое решение:** зафиксировать совместимые версии и проверить повторную установку.

### 14.2. Автоматизированное тестирование

**Наблюдение:** необходимо проверить полноту тестового покрытия и выполнение тестов в CI.

**Предлагаемое решение:** проанализировать и при необходимости дополнить тесты.

### 14.3. Управление конфигурацией

**Наблюдение:** необходимо проверить хранение настроек базы данных и секретов.

**Предлагаемое решение:** использовать переменные окружения и исключить секреты из репозитория.

> По результатам проверки создать минимум три GitHub Issues с метками `question` или `bug`.
