Лабораторная работа № 1. Запуск проекта
Паспорт проекта Whisper Mood
1. Общая информация
Название: Whisper Mood — веб-приложение для ведения личного дневника настроения.
Происхождение: собственный существующий проект, разработанный самостоятельно.
Репозиторий: https://github.com/pampixz/full-stack
Тип приложения: клиент-серверное веб-приложение.
Состояние проекта: существует реализованная версия приложения, требующая проверки воспроизводимости запуска, актуализации документации и совершенствования инженерных практик.

2. Назначение и решаемая проблема
Whisper Mood — веб-приложение, предназначенное для ведения личного электронного дневника, сохранения мыслей, событий и эмоциональных переживаний пользователя.
Проблема, которую решает проект, заключается в отсутствии единого удобного пространства для систематического ведения личных записей, отслеживания эмоционального состояния и организации связанной с этим информации.
Приложение предоставляет пользователю возможность сохранять записи в электронном формате, просматривать историю и управлять личными данными.
Цель проекта: создание удобной, безопасной и доступной веб-системы для ведения личного дневника с разграничением прав пользователей.

3. Целевая аудитория и пользовательские роли
Целевая аудитория: люди, желающие регулярно фиксировать свои мысли, эмоции, события и личные переживания.
В системе предусмотрены две роли.
3.1. Пользователь
Обычный пользователь может:
Регистрироваться в системе.
Авторизоваться в личном кабинете.
Создавать записи дневника.
Просматривать ранее созданные записи.
Редактировать и удалять собственные записи.
Искать необходимые записи.
Работать с вложениями.
Просматривать доступную информацию о встречах.
3.2. Администратор
Администратор обладает расширенными правами и может:
Авторизоваться в системе.
Использовать административные функции.
Управлять встречами.
Выполнять предусмотренные системой операции администрирования.

4. Три основные функции проекта
1. Регистрация и авторизация пользователей.
Создание учётной записи, вход в систему и разграничение доступа в зависимости от роли.
2. Управление записями дневника.
Создание, просмотр, редактирование, удаление и поиск личных записей.
3. Работа со встречами.
Просмотр информации о встречах и выполнение административных операций по управлению ими.

11. Внешние зависимости и конфигурация
Приложение использует базу данных MySQL.
Взаимодействие клиентской и серверной частей осуществляется через HTTP API.
Для запуска приложения используется Docker Compose.
Конфигурация приложения определяется файлами настройки и переменными окружения.
В проекте предусмотрено использование внешнего погодного API. Для соответствующей интеграции может потребоваться ключ доступа.
Точные версии инструментов и зависимостей фиксируются при проверке сборки.

14. Первые наблюдения о проблемах проекта
Проблема 1. Воспроизводимость сборки.
Необходимо проверить фиксацию версий Python-зависимостей и обеспечить воспроизводимую установку приложения.
Проблема 2. Автоматизированное тестирование.
Необходимо проверить полноту тестового покрытия и успешность выполнения тестов в CI.
Проблема 3. Управление конфигурацией.
Необходимо проверить способ хранения настроек базы данных и секретов, исключить попадание конфиденциальных данных в репозиторий.
По результатам проверки создаются соответствующие GitHub Issues.
