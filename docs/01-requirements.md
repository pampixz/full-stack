# Требования к Whisper Mood

Версия документа: **1.0**.

## 1. О приложении

Whisper Mood — веб-дневник для сохранения личных мыслей и эмоций. Гость регистрируется и входит; пользователь ведёт дневник и просматривает встречи; администратор дополнительно управляет встречами. На начало ЛР2 реализованы авторизация, CRUD записей, поиск, вложения, встречи и погодная интеграция. Планируются точная фильтрация тегов и надёжное хранение вложений.

Термины: User — аккаунт с ролью; Entry — запись дневника; EntryFile — вложение; Meeting — встреча; RefreshToken — токен обновления сессии.

### Конкретные примеры и ошибки

- US-1: новый email `lab2@example.com`, пароль `DiaryTest123!` → HTTP 200, `{"message":"User registered successfully"}`, создан User с ролью user. Повтор того же email → HTTP 400, `Email already registered`, второй аккаунт не создаётся.
- US-2: существующий `lab2@example.com`, пароль `DiaryTest123!` → HTTP 200, непустые access_token и refresh_token. Пароль `Wrong123!` → HTTP 401, `Invalid credentials`, новые токены не выдаются.
- US-4: авторизованный пользователь, текст `Сегодня хорошее настроение`, теги `["радость"]` → HTTP 201, ответ содержит новый целочисленный id, исходный текст, теги и created_at. Текст `а` → HTTP 422, сообщение валидации о минимальной длине 3, запись не создаётся.

Сообщения приведены на уровне API; точное отображение ошибок интерфейсом требует проверки. Примеры являются ожидаемыми результатами, не протоколом выполненных тестов.
